===== PAGINA 3 =====

NEO4J · BASES DE DATOS II



MERGE: comportamiento y propiedades


     MERGE (p:Persona {id: 101})
     ON CREATE SET p.nombre = 'Ana', p.alta = date()
     ON MATCH SET p.ultimoAcceso = datetime()
     RETURN p



    • ON CREATE SET se ejecuta únicamente si se crea el patrón.

    • ON MATCH SET se ejecuta cuando el patrón ya existe.

    • SET fuera de esas cláusulas se ejecuta en ambos casos.

===== PAGINA 5 =====

NEO4J · BASES DE DATOS II



MERGE no reemplaza las restricciones

     CREATE CONSTRAINT persona_id_unico IF NOT EXISTS
     FOR (p:Persona) REQUIRE p.id IS UNIQUE;

     MERGE (p:Persona {id: 101})
     SET p.nombre = 'Ana';




    • MERGE no elimina duplicados preexistentes.

    • Concurrencia: usar una clave única y su restricción.

    • Conviene evitar usar propiedades cambiantes como identidad.

===== PAGINA 13 =====

NEO4J · BASES DE DATOS II



Guía de respuestas y cierre

  • Con 2 de 3 primarios activos, puede elegirse nuevo líder y mantener quórum.

  • Con solo 1 de 3 primarios, no hay mayoría para nuevas escrituras.

  • Un secundario puede ir atrasado; bookmarks permiten esperar el progreso causal.

  • MERGE busca o crea patrones; UNIQUE protege la identidad ante concurrencia.

  • Raft = consenso; Causal Clustering = arquitectura distribuida.
