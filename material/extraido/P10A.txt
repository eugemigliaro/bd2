Instalación del motor

          Antes de comenzar si desean usar dockers/contenedores, sigan los siguientes pasos:
             ●​ Instalar Docker Desktop for Windows o for Mac o Docker Engine en Linux
             ●​ Para descargar la versión oficial de MongoDB: docker pull mongo
             ●​ Levantar el contenedor: docker run --name Mymongo -p 27017:27017 -d mongo
             ●​ Para levantar un Shell bash dentro del contenedor: docker exec -it Mymongo bash
             ●​ Para apagar el contenedor con: docker stop Mymongo
             ●​ Para iniciarla nuevamente: docker start Mymongo
             ●​ Para listar todos los containers existentes: docker ps -a
             ●​ Para copiar archivos del host al contenedor: docker cp <filename>
                 Mymongo:/<filename>

          Otra opción es instalar mongoDB, en su versión community, en la PC que vayan a utilizar
          para este práctico:
          Instalar MongoDB Community Edition - Manual de base de datos - MongoDB Docs

Instalación del cliente

          Una opción es utilizar el cliente de línea de comandos, para ello dentro de la terminal,
          ejecuten el comando mongosh para acceder a la Shell de MongoDB.

          Otra opción es utilizar DataGrip, configurando el data source correspondiente. Si quieren
          utilizar una GUI diferente a DataGrip, pueden optar por alguna de estas:
               ●​ MongoDB Compass (oficial): https://www.mongodb.com/products/tools/compass
               ●​ Robo 3T is now Studio 3T Free (open-source) : https://robomongo.org/download

Introducción

MongoDB es una base de datos de documentos, de código abierto que ofrece alto rendimiento, alta
disponibilidad y escalamiento automático.

Un registro en MongoDB es un documento, representado por una estructura de datos compuesta
por pares de campo y valor. Los documentos en MongoDB poseen formato JSON. Los valores de
los campos pueden incluir otros documentos, arreglos y arreglos de documentos.

SELECTORES

Los selectores permiten consultar documentos particulares dentro de la colección:
   ●​ {field: value} es usado para encontrar cualquier documento donde field sea igual a value
   ●​ {field1: value1, field2: value2} permite realizar una declaración and
   ●​ Los selectores especiales $lt, $lte, $gt, $gte y $ne son usados por las operaciones menor
       que, menor o igual que, mayor que, mayor o igual que y no igual respectivamente

     11.​Por ejemplo, para obtener todos los jugadores que tengan preferred_foot left y pesen más de
         170 libras (weight > 170), se puede utilizar el siguiente comando:
         db.players.find({preferred_foot: 'left', weight:{$gt:170}})

     12.​El operador $exists es usado para determinar la presencia o ausencia de un campo, por
         ejemplo para ver que documentos de la colección players no posee el campo height,
         ejecutar: db.players.find({height:{$exists:false}})

     13.​En caso de que se desee agregar una declaración con el operador OR, se utiliza $or seguido
         de un arreglo con los valores que se desean evaluar:
         db.players.find({preferred_foot:'right',
                        $or:[{hobbies:'Playing football'},
                                {hobbies:'Video games'},
                                {weight:{$lt:150}}]
                        })

EXPRESIONES REGULARES

MongoDB soporta expresiones regulares compatibles con Perl, para consultas basadas en patrones
de coincidencia identificados en las cadenas de caracteres.

     14.​Consultar todos los jugadores cuyo nombre comience por la letra S: db.players.find({name:
         { $regex: "^S"}})

     15.​Consultar todos los jugadores cuyo nombre termine con la letra o: db.players.find({name: {
         $regex: "o$"}})


COMANDOS DE ACTUALIZACIÓN

En su forma más simple, la operación update tiene dos argumentos: el selector (where) a usar y el
campo del documento a actualizar ($set).

     16.​Por ejemplo, el jugador que lleva por nombre Lionel Messi, ha subido de peso, por ello
         debemos actualizar el campo weight: db.players.updateOne({name: 'Lionel
         Messi'},{$set:{weight:180}})

     17.​Adicionalmente a $set, podemos aprovechar otros modificadores para hacer actualizaciones.
         Todos estos modificadores adicionales de update operan directamente sobre los campos del
         documento. Por lo tanto el documento completo no será reemplazado o borrado. Por
         ejemplo, el operador $inc es usado para incrementar o decrementar de acuerdo al parámetro
         que se utilice (positivo o negativo, respectivamente).

          Si a Luka Modric se le adjudicó incorrectamente un valor de 180 para el campo height,
          cuando debería ser 175, entonces ejecutar lo siguiente para corregirlo:
          db.players.updateOne({name: 'Luka Modric'},{$inc:{height:-5}})

     18.​Si David Silva de pronto desarrolla un gusto adicional por la natación, podemos agregarlo a
         su campo hobbies con el modificador $push (por tratarse de un arreglo).

          Primero ver los hobbies que tiene actualmente: db.players.find({name: 'David Silva'})
          Luego        realizar      el        push:      db.players.updateOne({name:           'David
          Silva'},{$push:{hobbies:'Swimming'}})

     19.​Los updates son compatibles con upserts. Un upsert actualiza el documento si lo encuentra o
         lo inserta si no lo encuentra. Los upserts son útiles de emplear en determinadas situaciones.
         Para habilitar upserting tenemos que especificar un tercer parámetro en true en el comando
         que utilicemos para el update.

          Un ejemplo aplicable de este caso es un contador de visitas a un sitio web. Si se desea
          mantener un recuento total, se tendría que validar si el registro ya existe para la página, y
          basado en eso decidir si ejecutar un update o un insert.

          Con el tercer parámetro omitido (o establecido en false), la ejecución de la siguiente
          instrucción no tendrá ningún resultado: db.hits.updateOne({page: 'players'},
          {$inc:{hits:1}});

SELECCIÓN DE CAMPOS

El comando find posee un segundo parámetro opcional. Este parámetro es la lista de los campos que
se desean obtener a la salida.

     23.​Si queremos obtener solo             todos    los   nombres     de    players    ejecutando:
         db.players.find({},{name:1});

     24.​Por defecto, el campo _id siempre es retornado. Podemos excluirlo explícitamente
         especificando: db.players.find({},{name:1, _id:0});

     25.​El método sort permite ordenar los resultados por los campos que se indiquen. Se utiliza 1
         para orden ascendente y -1 para descendente. Por ejemplo, podemos consultar los jugadores
         más altos primero: db.players.find({},{name:1, height:1,_id:0}).sort({height:-1})

     26.​También es posible paginar los resultados, a través de los métodos limit y skip. Para obtener
         solamente el segundo y tercer jugador más pesado, ejecuta el siguiente comando:
         db.players.find().sort({weight:-1}).limit(2).skip(1)

          Usando limit en conjunto con sort, es una buena forma de evitar problemas de performance
          cuando hacemos ordenamiento en campo sin índices.

     27.​Se puede ejecutar count directamente en una colección, para conocer el número de
         documentos          que        cumplen        con     determinada       condición:
         db.players.countDocuments({hobbies:'Swimming'})                                 o
         db.players.find({hobbies:'Swimming'}).count()

DOCUMENTOS EMBEBIDOS

En MongoDB el valor de un campo puede ser otro documento JSON, esto es útil por ejemplo para
simular JOINS.

     28.​Incorporémosle al jugador Cristiano Ronaldo, un documento con información
         correspondiente     a    su    equipo:       db.players.updateOne({name:      'Cristiano
         Ronaldo'},{$set:{team:{ team_long_name: 'Juventus', team_short_name: 'JUV'}}})

     29.​Los documentos embebidos también pueden ser accedidos usando la notación de punto:
         db.players.find({'team.team_short_name': 'JUV'})


ÍNDICES Y ADMINISTRACIÓN

Los índices en MongoDB funcionan muy parecido a los índices en una base de datos relacional,
ayudan a mejorar el rendimiento de los queries y ordenados.

     30.​Los índices son creados con el comando ensureIndex: db.players.ensureIndex({name:1})

     31.​Los índices pueden ser borrados usando dropIndex: db.players.dropIndex({name:1})

     32.​Un      índice     único    se      crea     utilizando        el     parámetro      unique:
         db.players.ensureIndex({name:1},{unique:true})

     33.​Los índices pueden ser creados en campos embebidos (usando la notación de punto) y en
         campos     de    arreglos.  También,     es posible    crear   índices compuestos:
         db.players.ensureIndex({name:1, weight:1})

     34.​Para validar si los queries están usando índices o no, se puede utilizar el método explain, al
         final de la consulta.

          Si se mantiene el índice del punto 32, veremos con la siguiente query que figura el nombre
          del índice que es usado: db.players.find({name: 'Lionel Messi'}).explain()
