===== PAGINA 28 =====

            Principales problemas de seguridad:

              • Control de acceso
              • Seguridad del código
              • Entradas maliciosas
Seguridad   Redis está diseñado para ser accedido por
            clientes de confianza dentro de entornos de
            confianza.

            No exponer la instancia de Redis directamente a
            Internet o acceder directamente al puerto o al
            socket.


            Prof. Dr. Guillermo Rodriguez - Ingeniería Informática ITBA

===== PAGINA 29 =====

             Redis no está optimizado para la máxima
             seguridad sino para un máximo rendimiento y
             simplicidad.


             Las aplicaciones que utilicen Redis como base de
             datos, caché o sistema de mensajería son las
Seguridad    encargadas de mediar entre este y los clientes
             que no son de confianza.

             El acceso no confiable a Redis siempre debe estar
             mediado por una capa que implementa ACL,
             valide la entrada del usuario y decide qué
             operaciones realizar contra la instancia de Redis.


            Prof. Dr. Guillermo Rodriguez - Ingeniería Informática ITBA

===== PAGINA 30 =====

             Un cliente puede autenticarse enviando el
             comando AUTH seguido de la contraseña.



             Cuando la capa de autorización está habilitada,
Seguridad    Redis rechazará cualquier consulta realizada por
             clientes no autenticados.


             AUTH ayuda a garantizar que las entidades
             conocidas en la organización no accedan y
             modifiquen la instancia de Redis de forma
             involuntaria. AUTH no brinda seguridad durante
             el transporte de datos.

            Prof. Dr. Guillermo Rodriguez - Ingeniería Informática ITBA
